# Translations

Translations are plain JSON files in `ui/i18n/`, one per language. No build step, no dependency. `en.json` is the source and the fallback for any missing key.

## Locale registry

`LANGUAGES` in `ui/js/i18n.js` is the one place a language is defined. Nothing else decides what is offered, what direction it reads, or how its name is spelled.

| Code | Language | Direction | Status |
| --- | --- | --- | --- |
| `en` | English | ltr | source |
| `fa` | Persian | rtl | machine |
| `zh-Hans` | Chinese (Simplified) | ltr | machine |
| `es` | Spanish | ltr | machine |
| `de` | German | ltr | machine |
| `fr` | French | ltr | machine |

Codes are BCP 47 tags. A code is also the catalog filename.

`status` is `source` for the language the strings are written in, and `machine`
for a catalog produced by machine translation. **A `machine` catalog has not
been checked by a speaker of that language.** It is complete and it is
structurally validated, but its wording is unverified. Treat a correction from a
speaker as authoritative over what is there now.

## Fallback

Fallback is per key, not per locale. A key missing from the selected language
falls back to English on its own, and the rest of the page stays translated.
There is no development fallback locale: English is the production fallback.

A key missing from English too renders as the key itself. That is visible in
the interface rather than blank, which is what makes the reachability test
worth having: it fails the build before a key can reach a reader.

## Counted messages

A message that shows a count is stored once per plural category, and the
category is chosen by the language's own rules:

```json
"loaded_one": "Loaded {count} option",
"loaded_other": "Loaded {count} options"
```

Call it with a numeric `count`:

```js
t('widgetCfg.loaded', { count: opts.length });
```

Do not choose the form in code. `count === 1` is an English rule: French and
Persian both put zero in `one`, Chinese has one form for every count, and other
languages have `few` and `many`.

Which categories a language uses is not a choice. Read them from the runtime:

```sh
node -e "console.log(new Intl.PluralRules('fr').resolvedOptions().pluralCategories)"
```

Every category that command lists must exist in that catalog, and no others. A
category a catalog does not carry falls back to `other`.

## Add a key

1. Add it to `ui/i18n/en.json`, under the section it belongs to.
2. Add the same key to the other five catalogs.
3. Reference it by its full dotted name, so the reachability test can see it:
   `t('general.logLevel')` or `data-i18n="general.logLevel"`.

A key that nothing references, and a reference to a key that does not exist,
both fail the test suite.

## Add a language

1. Add it to `LANGUAGES` in `ui/js/i18n.js`:

   ```js
   { code: 'it', name: 'Italiano', english: 'Italian', dir: 'ltr', status: 'machine' },
   ```

2. Copy `en.json` to `ui/i18n/it.json` and translate the values.
3. Copy `en.json` to `ui/widgets/<name>/i18n/it.json` for every widget and
   translate those too.
4. Split each counted message into the categories the language uses, as above.
5. Add the row to the table in this file.

The language then appears under Settings, General, Language.

## Translator notes

A translator changes JSON files only. No application code is involved.

- Translate values, not keys. Keep the JSON structure identical to `en.json`.
- Keep placeholders (`{count}`, `{name}`, ...) exactly as they are. A renamed or
  dropped placeholder takes the value out of the sentence.
- Keep the markup tags (`<strong>`, `<em>`, `<code>`, `<br>`) intact. No other
  tag renders; anything else is shown as text.
- Translate a whole message. Word order, articles and punctuation belong inside
  the message, because they move when the language changes.
- Proper nouns and technical tokens stay as they are: Unsplash, Docker, URLs,
  environment variable names, HTTP header names.

Terms with a fixed meaning here:

| Term | Meaning |
| --- | --- |
| tile | One item on the dashboard grid. |
| badge | The small status readout drawn on a tile. |
| folder | A tile that opens to hold other tiles. |
| widget | A tile that runs its own page in a frame. |
| Dock | The fixed row of tiles at the foot of the dashboard. |
| upstream | The service a tile points at, not Stackyard. |
| stale | Last reading is old; the service was not reached this time. |
| unavailable | The service answered, and it is not working. |

### Persian

One word per concept, taken from Persian that shipped software actually uses
rather than from the dictionary. Immich, Jellyfin and Uptime Kuma were read for
these; Immich is the closest to this project and ships
`وارد کردن پیکربندی` for "Import configuration" and `خروجی` for "Export".

| English | Use | Not |
| --- | --- | --- |
| Import | وارد کردن | درون‌ریزی |
| Export | خروجی | برون‌بری |
| Widget | ویجت | ابزارک |
| File | فایل | پرونده |

`ui/test/i18n-coverage.test.mjs` fails on any term in the "Not" column, in the
dashboard catalogue and in every widget catalogue. Add a row there and here
together when a term is decided.

## Development locales

Two locales exist for testing and are never offered in the selector. Reach them
by adding `?lang=` to the page URL, on the dashboard or on `/admin`.

```
http://localhost:8080/?lang=en-XA
http://localhost:8080/admin/?lang=cimode
```

`en-XA` accents every letter, pads the text by about 40% and brackets each
message. Text that clips, wraps badly, or was built by joining fragments shows
up while still being readable.

`cimode` loads no catalog, so every string renders as its own key. It names the
string under the cursor, and shows what is not going through the translation
system at all.

Neither is persisted. They live on the URL, so a reload without it is back to
normal.

## Validation

```sh
cd ui/test && node --test i18n.test.mjs i18n-reachability.test.mjs i18n-coverage.test.mjs widget-i18n.test.mjs i18n-markup.test.mjs
```

These check that every catalog carries the English key set, that every counted
message carries the plural categories its language uses, that no translation
changed or dropped a placeholder, that no value was left as the English, that
every key is referenced and every reference exists, and that no translation
carries markup outside the allowed tags.

They run offline. Nothing here contacts a translation service.

## Widgets

A widget is a sandboxed iframe and never loads the dashboard's i18n module, so a
widget cannot import `t` from `/js/i18n.js`. The selected code arrives on the
iframe URL as `lang`. The widget toolbox reads it to translate its own status
text from the catalog the dashboard already fetched.

The toolbox's own lookups use bare names under `widget.`, so `_t('loading')`
reads `widget.loading`. Add a key there when the toolbox itself needs a new one.

## A widget's own strings

Everything else a widget shows, in its settings form and in the widget itself,
comes from the widget's own folder:

```
ui/widgets/<name>/
  widget.json
  i18n/
    en.json      the source
    fa.json      one file per language
```

Both halves use the same keys. In `widget.json`, write the key where the text
would go:

```json
{ "key": "dnsUrl", "type": "text", "label": "dnsUrl.label", "hint": "dnsUrl.hint" }
```

`label`, `placeholder`, `hint`, `rowLabel` and `fetchLabel` are resolved this
way; everything else in a manifest is an identifier or a value and is left
alone. The API substitutes the selected language when it serves the manifest, so
the settings form receives plain strings.

In the widget's own page, ask the toolbox:

```js
import { loadStrings, wt } from '/js/widget-toolbox.js?v=1';
await loadStrings();               // before the first render
wt('ui.queriesBlocked', 'Queries Blocked');
```

Resolution is selected language, then the widget's `en.json`, then the text
passed in. A manifest carrying plain English therefore works with no catalog at
all. A bundled widget is held to more, see the catalog tests.

The toolbox has no counted-message form. A widget that needs one selects the
category itself with `Intl.PluralRules`.

See [widgets.md](./widgets.md).
